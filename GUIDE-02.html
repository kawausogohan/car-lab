2．ギアと坂道

めあて：低いギアは、坂を登る力を大きくする。

  1. 1速でアクセルを押して走ります。
  2. 同じ坂で5速も試し、登り方と下に出る「起きたこと・理由」を比べます。
  3. 「坂・コース」で条件を変えて試します。ランキングと実験ノートは右上の☰から開けます。

走行、1〜5速、タコメーター、ランキングの条件・保存形式は維持しています。詳しい力のメーターは☰ →「しくみ・メーター」、技術的な説明と音量は☰ →「あそび方」です。キー操作はW/↑＝アクセル、S/↓＝ブレーキ、1〜5＝ギア、Q/E＝1段変速、Space＝一時停止です。

3．エンジンの4ストローク

めあて：エンジンは、4つの工程をくり返して力をつくる。

  1. 下の大きな工程ボタンを押します。選んだ工程だけがゆっくり動き、終わりで止まります。同じボタンで何度でも繰り返せます。
  2. 吸気では青緑の流れが入り、排気では茶色の流れが外に出ます。図の下の「空気 ＋ ガソリン」「閉じこめた混合気」「火花 → 燃える → 押す」「燃えたあとのガス」は、縮小される図内文字から独立した22〜25pxの大きな表示です。工程に合わせて言葉と色が切り替わります。
  3. 燃焼・膨張では、プラグの火花で燃えたガスがピストンを押すことを説明します。
  4. 「4つをつなげて再生」で全体を観察。「ここで止める」「ゆっくり」と角度のつまみで、好きな位置を確認できます。

「しくみ・音量」から、細かい角度・実験・修理・研究ノートと、これまでの点火ゲームを開けます。既存のノート・ミッション・修理・ゲームの記録は削除していません。

4．エンジンからタイヤまで

タイヤを、厚い黒いゴム・溝・6本スポークのホイールが見える斜めからの描写へ変更しました。選んだ駆動輪には光の輪がつき、ホイールと溝は車速に合わせて回ります。

FF：前の2輪 ／ FR：後ろの2輪 ／ 4WD：4つのタイヤ。図の上の大きなボタンで選び、同じアクセルで力の送り先を比べます。駆動していないタイヤも、車といっしょに転がります。

めあて：エンジンの力は、部品を通ってタイヤへ伝わる。

  1. 最初はクラッチが切れています。アクセルを増やすとエンジンだけ速く回り、静止しているタイヤには力が届きません。
  2. 「クラッチをつなぐ」を押します。半クラッチの補助で徐々につながり、緑の光をクランク → クラッチ → 変速機 → プロペラシャフト → デフ → 後輪まで追えます（FRの場合）。FFでは前輪側のデフへ、4WDではセンターデフから前後それぞれのデフへ分かれます。
  3. もう一度クラッチを切ります。力はそこで途切れ、タイヤは勢いで回り続けてからゆっくり止まります。
  4. 部品の図、または下の部品ボタンを押すと、役割が一文で出ます。青い光は、アクセルを戻したときなどにタイヤ側からエンジンへ戻る力の向きです。

直列4気筒の4つのピストンと1本のクランクを表示します。1・4番、2・3番は同じ高さで動き、燃焼順序は1→3→4→2です。モデルの詳細は「しくみ・音量」にまとめています。

5．音の管理

全作品とも最初は音OFF。上部の音ボタンを押してから鳴ります。音量は「あそび方」または「しくみ・音量」で変更できます。音ボタンでミュートに戻せます。

エンジン音は4気筒4ストロークの燃焼周期をもとに、排気のパルスと吸気のノイズを端末内で合成しています。回転数で音の高さ、アクセル開度と負荷で音色・大きさ、変速中は短い出力の抜けを変えています。実車の録音や特定車種の音ではありません。外部の音源・通信には依存しません。

編集する場合は car-lab/lab-audio.js が共通の音処理です。編集後は配布用HTMLを生成し直してください。音量・ON/OFFはページごとに戻るため、ページを移動すると再び無音で始まります。

6．既存の保存データ

ギアのランキング・走行記録は car-lab.records.v2、エンジンの研究ノートは car-lab.engine.progress.v1 のままです。点火ゲームの記録キー car-lab.engine.game.v1 と car-lab.engine.beat.v1 も維持しています。新しい工程観察と第3弾は、これらのデータを読み書きしません。

同じGitHub PagesのURL・同じブラウザで更新する場合は、既存の記録を引き続き使います。更新前に、ギアのランキング →「記録の保存・持ち運び」でJSONを書き出し、エンジン研究モードでもノートのJSONを書き出すと持ち運べます。点火ゲームのスコアや星は、そのノートJSONには含まれません。

ファイル版、公開URL、別端末の間では記録は自動移行しません。file://で開く場合の保存範囲はChromeの扱いに依存します。ファイルの移動前には書き出した記録も保管してください。

7．検証したこと・実機で確認すること

改修前は146件、既存2作品のUI・音の改修後は155件、第3弾の初版は172件、今回のタイヤ・FF・FR・4WD改修後は183件の自動検査がすべて通りました。既存2作品の改修・検査を終えてから第3弾を実装しています。

計算、入力イベント、ランキング・ノートの互換性、工程の反復、全0〜720°の操作、点火・カムの関係、4気筒の位相と燃焼順序、クラッチの切断・惰性・逆駆動、速度比、合成音の制御を検査しました。停止・非表示時に観察アニメーションを止めること、旧データを変更しないことも確認しています。今回、各駆動方式で正しい車輪に光が届くこと、FFから後輪用シャフトを除くこと、4WDの前後配分、切り替えで力やエネルギーが増えないこと、大きな気体ラベルと工程が一致することを追加検査しました。描画命令の検査であり、実画面での評価ではありません。HTML構造・リンク・配布用プログラムの一致も別途検査しています。

自動検査はDOM・Canvas・音声APIの代用品です。ローカルHTMLの自動ブラウザ操作がこの環境のポリシーで制限されているため、今回の実画面でのプレイ、実際に聞いた音、Chromebook実機のタッチ・描画速度は未確認です。代用品での検査を、実機のプレイ済みとは扱っていません。

  1. 学校のChromebookを横向きにし、03までの大きなボタンですぐ切り替えられることを確認します。小さめの画面では縦にスクロールできます。
  2. ギア編で1速と5速、同じ坂を比べます。走行後に以前のランキングとノートが残っているか見ます。
  3. 4ストロークの工程を各2回繰り返し、工程名・流れ・短い説明を読みます。つまみで止め、プラグとバルブを観察します。
  4. 第3弾でアクセル、接続、切断を順に操作し、力の光とタイヤの惰性を見ます。FF・FR・4WDを切り替え、前の2輪・後ろの2輪・4輪にだけ光の輪が出るかを見ます。部品や部品ボタンも押します。4WDではセンターデフのボタンも現れます。
  5. 音ON、音量の小・大、ミュート、ページ切り替え、一時停止を試します。画面が止まらず、音が不自然に残らないか確認します。
  6. 子どもに「今、何を試す画面？」「どうして動きが変わった？」と聞き、ひとつのめあてにつながる言葉が返るか見ます。

8．GitHub Pagesへ更新する

公開先は今までどおり kawausogohan/car-lab。main ／ root設定は変更しません。この作業では、公開中のサイトへアップロードしていません。

  1. CAR-LAB-drive-modes.zipを展開します。
  2. GitHubのリポジトリで Code → Add file → Upload files を開きます。
  3. 展開した中身を追加します。ルートの index.html、engineフォルダー、drivelineフォルダー、ガイドなどです。ZIPや包んでいる親フォルダーそのものは追加しません。
  4. engine/index.html、engine/beat.html、engine/lab.html、driveline/index.htmlが、それぞれのフォルダー内にあることを確認して Commit changes を押します。
  5. Actionsの公開処理が完了してからサイトを再読み込みします。古い画面が出る場合は、Ctrl+Shift+Rでキャッシュを使わず再読み込みします。

9．簡略化した点と、編集・検査

ギア編の物理モデルと順位処理、4ストロークの機構計算は変更していません。ピストンは有限長コンロッドの幾何から求め、クランク2回転に対しカム1回転。4ストロークの点火は圧縮上死点360°、理想化したバルブタイミングです。実車では点火時期や開閉時期が前後します。主な仕事を取り出すのは燃焼・膨張です。

第3弾はFF・FR・フルタイム4WDの教材用比較、1速固定。全回転を同じ1/70に落として描きます。エンジン速度の調節と半クラッチは教材用の補助、変速機とデフは理想的で損失を省略しています。クラッチのすべりによる損失と、車体の慣性・抵抗は計算します。図は断面を並べた模式図で、実車の形状・寸法・配置そのものではありません。FFの折れ線は部品を広げた接続の図で、長いプロペラシャフトではありません。4WDは理想的なセンターデフで前後50:50、それぞれのデフで左右へ分けます。路面で空転しない同条件なので、方式だけで加速を変えていません。切り替えは3つの教材の比較で、実車の走行中操作の再現ではありません。光は動力の経路を示すもので、物質が流れる表示ではありません。

ソースのcar-labフォルダー内で以下を実行すると、隣のpublishへ配布用HTMLを作り直せます。プレイするChromebook側でこの作業は不要です。

node --test tests/*.test.cjs
node tools/build-single.cjs
node tools/validate-package.cjs
